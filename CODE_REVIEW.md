Объект ревью: `index.html` (single-file приложение, 1696 строк, коммит `763ec75`).
Дата: 2026-09-04.

## 1. Резюме

Приложение решает понятную задачу и в целом сделано аккуратно: чистая дизайн-система на
CSS-переменных, поддержка тёмной темы, разумное разделение на секции, вменяемые русские
комментарии. Но в нём есть **одна дыра в безопасности, два «тихих» логических бага, из-за
которых инструмент показывает неверную картину, и несколько мест, которые гарантированно
разваливаются на промышленных объёмах данных**.

Самое важное:

| # | Проблема | Тяжесть | Статус |
|---|----------|---------|--------|
| 1 | XSS: данные из XLSX попадают в DOM без экранирования | 🔴 критично | исправлено |
| 2 | Аудит модели всегда пуст после загрузки файлов | 🔴 критично | исправлено |
| 3 | Мультизагрузка файлов работает недетерминированно | 🔴 критично | исправлено |

| 5 | `0` в данных подменяется на значение по умолчанию | 🟠 высоко | исправлено |
| 6 | Тумблер «Предупреждения» не делает того, что обещает | 🟠 высоко | исправлено |
| 7 | Расстановка узлов сбрасывается при любом действии | 🟠 высоко | исправлено |

## 2. Критические дефекты

### 2.1 🔴 XSS через содержимое XLSX

Весь HTML собирался конкатенацией строк и вставлялся через `innerHTML` без экранирования.
Затронуты были все точки вывода: боковое дерево, оба фильтра, матрица, все пять таблиц.

```js
// было — renderSidebarNodes()
html += `<label class="sb-item ${isChecked ? 'on' : ''}">
  <input type="checkbox" onchange="toggleFilterNode('${n.id}')">
  <span>${n.id}</span>
</label>`;
```

Здесь **две независимые инъекции**:

1. `<span>${n.id}</span>` — имя локации `<img src=x onerror=...>` из файла выполнит код.
2. `onchange="toggleFilterNode('${n.id}')"` — гораздо хуже: инъекция прямо в JS-контекст
   атрибута. Причём сюда достаточно **обычного апострофа**, без всякого злого умысла:
   локация `ООО "Северсталь"` или `Цех п/ф` ломает разметку и обработчик перестаёт работать.

Модель угроз реальная: файлы приходят из внешних учётных систем и от смежников, а
приложение — не «просто картинка», оно живёт на корпоративном домене рядом с
`localStorage` и сессионными куками.

Та же проблема в матрице, где неэкранированный текст шёл ещё и в атрибут:

```js
const title = lanes.map(l => `${l.item} (${l.mot}) - ${l.leadtime}дн`).join('\n');
html += `<td class="matrix-cell-active" title="${title}">${lanes.length} плеч</td>`;
```

**Исправлено:** введена функция `esc()`, через неё проходит **каждое** интерполируемое
значение; inline-обработчики полностью убраны и заменены делегированием событий с
`data-`атрибутами. Проверено тестом: имена вида `<img src=x onerror=...>` и `Зло'"><b>tag`
попадают в DOM как текст, ноль внедрённых узлов.

### 2.2 🔴 Аудит модели всегда пуст после загрузки данных

Две функции противоречили друг другу. `deriveSkuFromLoadedData()` достраивала SKU-матрицу,
добавляя в `MODEL.sku` **все** пары «продукт × локация» из `tlane` и `prodsource`:

```js
MODEL.tlane.forEach(t => { addPair(t.item, t.locfr); addPair(t.item, t.locto); });
```

А сразу за ней `runModelAudit()` строила эталон известных локаций из этого же массива:

```js
const knownLocs = new Set([...MODEL.sku.map(s => s.loc), ...MODEL.res.map(r => r.loc)]);
if (t.locfr && hasMaster && !knownLocs.has(t.locfr)) { /* никогда не выполнится */ }
```

Проверка «локация не описана в справочниках» физически не могла сработать: искомые
локации только что были добавлены в справочник автоматически. То же с проверкой PDS → SKU.

Подтверждено прогоном на изолированной копии логики:

```
Аудит БЕЗ derive (демо-данные):        [ 'ERR locfr Ghost_1' ]
Аудит ПОСЛЕ derive (загруженный файл): []
```

Получалось, что на демо-данных счётчик показывал замечания, а стоило загрузить настоящий
файл — «0 предупреждений» **всегда**. Ровно тот сценарий, ради которого инструмент и нужен.
Это опаснее обычной ошибки: пользователь получает ложное подтверждение, что модель чистая.

**Исправлено:** авто-достроенные строки помечаются `derived: true` и исключены из состава
мастер-данных. Проверка снова находит `Ghost_1`, а в таблице SKU такие строки помечены
бейджем «авто», чтобы было видно, где реальные данные, а где домысел приложения.

### 2.3 🔴 Мультизагрузка файлов — гонка и потеря данных

Кнопка прямо приглашала выбрать несколько книг (`multiple`, подсказка «sku, res,
prodsource, tlane»), но обработчик запускал `FileReader` на все файлы параллельно и писал в
`MODEL` из колбэков:

```js
parseWorkbookSheets._wipeNext = true;
files.forEach(file => {
  const reader = new FileReader();
  reader.onload = (evt) => parseWorkbookSheets(XLSX.read(evt.target.result, {type:'array'}));
  reader.readAsArrayBuffer(file);
});
```

Отсюда сразу четыре дефекта:

* **Порядок завершения случайный** — зависит от размера файлов, не от порядка выбора.
* **Флаг `_wipeNext` сбрасывался первым же завершившимся ридером**, остальные подмешивались
  к уже очищенной модели непредсказуемо.
* **`MODEL.sku = ...` перезаписывает, а не дополняет** — при загрузке четырёх файлов
  выживал только последний, содержавший соответствующий лист.
* **`deriveSkuFromLoadedData()` и `runModelAudit()` вызывались после каждого файла**, то есть
  на заведомо неполной модели, оставляя мусорные `derived`-строки, которые уже не убирались
  приходом настоящего справочника.

**Исправлено:** `importFiles()` читает книги **последовательно** (`async/await`), собирает всё в
промежуточный объект, и только потом одной транзакцией обновляет модель, достраивает SKU,
пересчитывает аудит и перерисовывает интерфейс.

## 3. Функциональные дефекты

### 3.1 🟠 Ошибки импорта проглатывались

`XLSX.read()` не был обёрнут в `try/catch`, у `FileReader` не был назначен `onerror`.
Битый файл, PDF с расширением `.xlsx`, книга без нужных листов — во всех случаях
пользователь видел ровно ничего: интерфейс не менялся, сообщения не было, исключение
уходило в консоль. Отличить «файл не подошёл» от «приложение сломалось» было невозможно.

**Исправлено:** ошибки перехватываются на каждом файле; итог сообщается тостом с разбивкой
(`sku: 120 · tlane: 340`), непрошедшие файлы перечисляются отдельно с причиной; на время
разбора показывается индикатор.

### 3.2 🟠 Значение `0` подменялось умолчанием

```js
leadtime: numCol(...) || 1,
capacity: numCol(...) || 24,
outputqty: numCol(...) || 1
```

Идиома `|| default` срабатывает не только на «нет данных», но и на честный ноль:

| Данные в файле | Было в модели | Должно быть |
|---|---|---|
| `leadtime = 0` (доставка день в день) | `1` | `0` |
| `capacity = 0` (ресурс остановлен) | `24` | `0` |

Приложение молча искажало исходные данные — и остановленный ресурс выглядел работающим.

**Исправлено:** `orDefault(v, def)` применяет умолчание только при `null`/`undefined`.
Заодно добавлена проверка аудита на нулевую мощность — теперь это видимое замечание,
а не тихая подмена.

### 3.3 🟠 Разбор чисел ломался на русском формате

```js
const numCol = (v) => parseFloat(String(v).replace(',', '.'));
```

Заменялась только **первая** запятая, пробелы-разделители не удалялись:

| Вход | Было | Стало |
|---|---|---|
| `1 234,5` | `1` | `1234.5` |
| `1.234.567,89` | `1.234` | `1234567.89` |

Для выгрузок из 1С/SAP с русской локалью это массовое искажение чисел.
**Исправлено:** `toNum()` понимает неразрывные пробелы, точки и запятые как разделители
тысяч и десятичных по позиции последнего разделителя.

### 3.4 🟠 Тумблер «Предупреждения» вёл себя не так, как показано

Три отдельные проблемы в одной функции:

```js
const auditLocs = SHOW_WARNS_ONLY ? new Set(MODEL.audit.flatMap(a =>
  a.obj.split(/→|·/).map(s => s.trim()))) : null;
```

1. **Локации извлекались разбором текста.** Для записей категории `PDS/BOM` поле `obj`
   содержит код рецепта (`F_PIP_HF_OBSO_000285_TMZ_0007`), а не локацию — в множество
   попадал мусор.
2. **Узлы не затенялись без активного фокуса.** Ветка затенения начиналась с
   `if (lineage && !isNodeHighlighted)`, то есть при выключенном фокусе `matchesAudit`
   не влиял на узлы вообще.
3. **Но подписи рёбер пропадали** — `if (GRAPH.zoom > 0.65 && isVisible)` учитывал аудит.
   Итог: пользователь включает тумблер, узлы не меняются, а подписи молча исчезают.

Плюс при пустом аудите множество оказывалось пустым и скрывало вообще всё.

**Исправлено:** каждая запись аудита несёт машиночитаемый список `locs: []` — разбор текста
регулярками устранён. Режим подсветки работает независимо от фокуса, корректно совмещается
с ним, обводит проблемные узлы красным, а при отсутствии замечаний честно сообщает, что
подсвечивать нечего.

### 3.5 🟠 Расстановка узлов сбрасывалась при любом действии

`buildGraphTopology()` пересоздавала объекты узлов с нуля, а `refreshUI()` вызывала её на
**каждое** изменение фильтра, клик по узлу и переключение вкладки. Пользователь аккуратно
раскладывал схему — один клик по чекбоксу, и всё вернулось.

**Исправлено:** перетащенные узлы попадают в `PINNED` и переживают перерисовку.
Двойной клик открепляет один узел, кнопка «Пересобрать раскладку» (`R`) — все.

### 3.6 🟡 Раскладка не отражала топологию

Колонки строились по **типу** локации (`rank` из `getNodeCategory`), а не по реальным связям:

```js
const rankGroups = {};
nodes.forEach(n => { rankGroups[n.rank || 3].push(n); });
```

Для сети «завод → завод → завод» все узлы попадали в одну колонку, и последовательность
переделов — главное, ради чего смотрят на такую схему — не читалась.
Классификация вдобавок опиралась только на латинские префиксы (`PLANT`, `PORT`), поэтому
кириллические названия («Завод_1») сваливались в «Прочие».

**Исправлено:** послойная раскладка по фактическому графу (longest-path layering с защитой
от циклов) плюс упорядочивание внутри слоя по барицентру для снижения числа пересечений.
Категории распознают и кириллические префиксы. Проверено: цепочка
`Vendor_1 → Plant_1 → Port_1 → Sale_1` раскладывается в четыре колонки (x = 60, 276, 492, 708).

### 3.7 🟡 Параллельные плечи рисовались друг поверх друга

Каждая строка `tlane` давала отдельное ребро. Пять SKU по маршруту «Завод → Порт» — пять
одинаковых кривых с наложенными подписями. Петли (`locfr === locto`) вырождались в точку.

**Исправлено:** рёбра сворачиваются по паре «откуда → куда», толщина отражает число плеч,
подпись — `N продукт. · M плеч`, детали доступны в тултипе. Петли рисуются дугой.

### 3.8 🟡 Глобальные обработчики и «мёртвый» интерфейс

* `window.onmousemove` / `window.onmouseup` присваивались напрямую, затирая любые другие
  обработчики и продолжая работать в режиме матрицы, где холст скрыт и `getBoundingClientRect()`
  возвращает нули. Заменено на `addEventListener` + Pointer Events (заодно появилась
  поддержка тач-устройств и жеста pinch-to-zoom).
* Элемент `#graphTip` был описан в HTML и стилизован в CSS, но **JS не показывал его никогда** —
  ~20 строк мёртвого кода. Теперь это рабочие тултипы узлов и рёбер.
* Ячейки матрицы имели `cursor: pointer` и hover-подсветку, но клик ничего не делал —
  обманчивая аффорданс. Теперь ведут к цепочке узла.
* Легенда перечисляла 5 категорий из 6 — «Прочие узлы» отсутствовали. Теперь строится
  из того же справочника, что и раскраска, — рассинхрон исключён.
* Масштабирование колесом привязывалось к левому верхнему углу, а не к курсору.

### 3.9 🟡 `roundRect` без полифилла

`ctx.roundRect()` используется в отрисовке узлов и подписей. В Safari он появился только в
16.4 (март 2023); в старых WebView и корпоративных браузерах вызов бросает исключение и
**рушит всю отрисовку графа** — пользователь видит пустой холст без объяснений.
Добавлен полифилл через `arcTo`.

### 3.10 🟡 Сопоставление листов книги было хрупким

```js
const match = Object.keys(sheetMap).find(k => k.includes(normalizeKey(a)));
```

Поиск по вхождению подстроки без приоритета точного совпадения и без исключения уже
занятых листов: книга с листами `sku` и `sku_archive` могла отдать не тот лист, а результат
зависел от порядка листов в файле. **Исправлено:** два прохода (сначала точные совпадения,
затем частичные) с исключением уже сопоставленных листов.

## 4. Производительность

Замеры делались на синтетике 5000 плеч / 300 локаций.

| Проблема | Было | Стало |
|---|---|---|
| `canvas.width = w * dpr` на **каждом** кадре — полный сброс контекста и буфера | пересоздание при каждом движении мыши | только при реальном изменении размера |
| Перерисовка синхронно из `mousemove` | до 100+ кадров/сек впустую | throttle через `requestAnimationFrame` |
| `FILTERS.items.includes(...)` в циклах рендера | O(n²) | `Set`, O(1) |
| Полный `innerHTML` всех строк | 10 000 строк → зависание вкладки | лимит 400 строк + «показать ещё» + экспорт |
| Матрица N×N | 300×300 = 90 000 ячеек | ограничение 120×120 с явным предупреждением |
| Поиск и `resize` без debounce | ререндер на каждую букву | debounce 120–160 мс, `ResizeObserver` |
| `getLineageInfo` — `while(changed)` по всем рёбрам | O(V·E) | BFS по спискам смежности, O(V+E) |
| Обнаружение циклов | отсутствовало | итеративный DFS без рекурсии (не переполняет стек) |

Результат прогона: 5000 плеч → 300 узлов, полный цикл «разбор + аудит + раскладка +
рендер» за **194 мс**, в DOM 400 строк вместо 5000.

## 5. Улучшения для конечного пользователя

Помимо исправлений, добавлено то, чего инструменту не хватало для ежедневной работы.

**Онбординг.** Раньше требуемая структура книги нигде не была описана — только в `title`
кнопки. Теперь есть **скачиваемый шаблон XLSX** с готовыми листами, колонками, примерами и
листом README, а пустое состояние холста объясняет, что делать дальше.

**Экспорт** (SheetJS уже был подключён, но использовался только на чтение):
* все таблицы в XLSX с учётом текущих фильтров, включая лист аудита;
* текущая вкладка в CSV с BOM (иначе Excel показывает кириллицу «кракозябрами»);
* граф в PNG — **вся схема целиком**, а не только видимая часть экрана, в 2× разрешении.

**Сохранение сессии.** Раньше переживала перезагрузку только тема. Случайный F5 уничтожал
результат загрузки четырёх книг. Теперь сохраняются и данные модели (с защитой по объёму),
и раскладка интерфейса: режим, вкладка, высота панели, состояние сайдбара.

**Работа с таблицами.** Сортировка по клику на заголовок, сквозной поиск, счётчик
«показано N из M», переход к узлу графа кликом по локации в таблице.

**Управление схемой.** Кнопки зума, «вписать в экран», «пересобрать раскладку», индикатор
масштаба; тултипы с составом узла (SKU, ресурсы, рецептуры, замечания) и ребра (плечи,
транспорт, диапазон сроков); зум к курсору; перетаскивание файлов прямо на окно.

**Клавиатура:** `Esc` — сброс фокуса/меню, `/` — поиск узла, `F` — вписать, `R` — пересобрать,
`G`/`M` — граф/матрица, `+`/`−` — масштаб. Работает и в русской раскладке.

**Доступность.** `<a>` без `href` заменены на `<button>`; тумблер стал `role="switch"` с
`aria-checked`; у меню — `aria-expanded`/`aria-haspopup`; добавлены `aria-label`, видимый
фокус, поддержка `prefers-reduced-motion`. Ресайзер больше не выделяет текст при
перетаскивании и управляется стрелками.

**Адаптивность.** Медиазапросы для узких экранов, сайдбар оверлеем на мобильных,
Pointer Events вместо мышиных — граф работает на планшете.

**Расширенный аудит.** Было 2 проверки (обе нерабочие после загрузки), стало 15:
незадекларированные локации, петли, циклы в цепочке, дубли плеч и SKU, ссылки на
несуществующие ресурсы, `min > max` партии, нулевые мощности и нормы, конфликт кодов
рецептов, изолированные узлы и тупики. Уровни `Критично / Внимание / Инфо`, счётчик в
шапке меняет цвет по худшему уровню.

## 6. Что стоит сделать дальше

Осознанно не вошло в эту итерацию.

1. **Сборка из модулей.** Один файл на 2900 строк удобно передавать по почте и открывать с
   диска — это, судя по всему, сознательный выбор, и я его сохранил. Но при дальнейшем росте
   стоит перейти на Vite с раздельными модулями (`model`, `parse`, `audit`, `graph`, `ui`) и
   собирать в один HTML плагином `vite-plugin-singlefile` — портативность сохранится.
2. **Тесты.** Логика разбора, аудита и раскладки — чистые функции, их легко покрыть Vitest.
   Сейчас регрессии ловятся только глазами. Сценарии из моего smoke-теста — готовая основа.
3. **Локальные копии зависимостей.** SheetJS и шрифт грузятся с CDN без SRI и без фолбэка.
   За корпоративным фаерволом импорт просто не работает (сейчас об этом хотя бы честно
   сообщается тостом). Стоит положить библиотеку рядом с файлом и добавить `integrity`.
4. **Виртуализация таблиц** вместо лимита в 400 строк — при регулярной работе с сотнями тысяч
   плеч постраничная подгрузка станет неудобной.
5. **Разбиение по компонентам связности** — для сетей на тысячи узлов имеет смысл показывать
   подсети отдельно и давать переключатель между ними.
6. **Расчётные метрики:** суммарный лидтайм по цепочке, критический путь, узкие места по
   мощности. Данные для этого в модели уже есть, а ценность для планировщика высокая.
7. **Undo/redo** для фильтров и раскладки.
